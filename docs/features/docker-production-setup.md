# Docker Production Setup

## Overview

Production deployment for HTUT AI on a single VPS: the **host nginx** (which also serves other projects on :80/:443, TLS via certbot) reverse-proxies to the serversideup PHP container published on `127.0.0.1:8080`, with dedicated queue worker and scheduler containers. Images are built by GitHub Actions, pushed to GHCR, and deployed over SSH.

```
ai.htut.com ──A record──► VPS IP
   ▼
host nginx :80/:443 (certbot TLS, shared with other projects)
   ▼ proxy_pass http://127.0.0.1:8080
php :8080 (published on localhost only)
queue · scheduler · mysql · redis  ← no public ports
```

## Files

| File | Purpose |
|---|---|
| `Dockerfile` | Multi-stage build (see below) |
| `.dockerignore` | Keeps secrets/dev artifacts out of the image |
| `docker-compose.production.yml` | Production stack (`htut-ai-prod` project) |
| `deploy/nginx-ai.htut.com.conf.example` | Host-nginx site block → `proxy_pass http://127.0.0.1:8080` |
| `.env.production.example` | Template — real `.env.production` lives only on the VPS |
| `.github/workflows/deploy.yml` | Build → GHCR → SSH deploy on push to `main` |

## Image design

Three stages — required because Wayfinder output (`resources/js/{actions,routes}`) is **gitignored** and must be generated by artisan before the frontend can compile:

1. **vendor**: `serversideup/php:8.4-fpm-nginx` + `composer --no-dev` + `artisan wayfinder:generate`
2. **assets**: `node:20-alpine` + `npm ci` + committed font cache (`node_modules/.cache/laravel-vite-plugin`, ~200K) + `npm run build` — no network fetch of fonts.bunny.net at build time
3. **final**: base image + source + vendor + baked `public/build`; stale `bootstrap/cache/*.php` removed (dev manifests may reference dev-only providers)

Ownership is set at `COPY --chown=www-data` time (the container user cannot chown).

## One-time VPS setup

```bash
# 1. Create a DigitalOcean droplet (Ubuntu 24.04), then as root:
apt update && apt install -y docker.io docker-compose-v2 git nginx ufw
ufw allow OpenSSH && ufw allow 80,443/tcp && ufw enable

# 2. Clone the repo
mkdir -p /var/www && cd /var/www
git clone git@github.com:AI-Face-Swap/admin-dashboard.git htut-ai
cd htut-ai
#    (add the server's SSH key as a read-only Deploy Key in GitHub)

# 3. Configure environment
cp .env.production.example .env.production
nano .env.production        # fill EVERY placeholder (DB password, keys, Spaces…)

# 4. Generate the app key without writing any file:
docker compose --env-file .env.production \
  -f docker-compose.production.yml run --rm php php artisan key:generate --show
nano .env.production        # paste into APP_KEY=

# 5. First boot (migrations run automatically via AUTORUN_ENABLED)
docker compose --env-file .env.production \
  -f docker-compose.production.yml up -d
docker compose --env-file .env.production -f docker-compose.production.yml ps
curl http://127.0.0.1:8080/healthcheck     # → OK

# 6. Host-nginx site + TLS (see deploy/nginx-ai.htut.com.conf.example header):
cp deploy/nginx-ai.htut.com.conf.example /etc/nginx/sites-available/htut-ai
ln -s /etc/nginx/sites-available/htut-ai /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx
certbot --nginx -d ai.htut.com             # adds the :443 block + redirect
```

## GitHub Actions secrets

| Secret | Value |
|---|---|
| `SSH_HOST` | VPS public IP |
| `SSH_USER` | root (or a sudo-less deploy user) |
| `SSH_KEY` | Private key whose public half is authorized on the VPS |

`GITHUB_TOKEN` is provided automatically for GHCR pushes. The first push creates the private package `ghcr.io/ai-face-swap/admin-dashboard`; if the VPS pull is denied, create a PAT with `read:packages` and run `docker login ghcr.io` on the VPS once.

## DNS (when the domain arrives)

At the registrar for `htut.com`:

```
Type: A · Name: ai · Value: <VPS_PUBLIC_IP> · TTL: default
```

Once DNS resolves, run `certbot --nginx -d ai.htut.com` on the VPS to issue the
Let's Encrypt certificate and add the HTTP→HTTPS redirect, then set
`APP_URL=https://ai.htut.com` in `.env.production`. Laravel trusts the proxy
(`trustProxies` in `bootstrap/app.php`), so https URLs and client IPs are
correct out of the box.

## Deploys & rollback

```bash
git push                      # to main → build + deploy automatically
                              # (or Actions → Build & Deploy → Run workflow)
```

Deploy = pull new image → recreate changed services; `AUTORUN_ENABLED` runs `php artisan migrate --force` on each php start.

Rollback to any previous build:

```bash
cd /var/www/htut-ai
IMAGE_TAG=<short-sha> docker compose --env-file .env.production \
  -f docker-compose.production.yml up -d
```

## Ops commands

Convenient Make wrappers exist for everything below (`make prod-up`, `prod-down`, `prod-ps`, `prod-logs s=<service>`, `prod-shell`, `prod-migrate`, `prod-deploy`, `prod-rollback SHA=<sha>`) — see **`DOCKER.md`**. Raw forms:

```bash
docker compose --env-file .env.production -f docker-compose.production.yml ps
docker compose --env-file .env.production -f docker-compose.production.yml logs -f php
docker compose ... exec php php artisan tinker
docker compose ... exec php php artisan optimize:clear
docker compose ... down          # volumes survive
```

## Healthchecks

| Service | Check |
|---|---|
| `php` | NGINX-level `GET /healthcheck` (served by the base image) |
| `mysql` | `healthcheck.sh --connect --innodb_initialized` |
| `redis` | `redis-cli ping` |
| `queue` | `queue:work` process alive (`pgrep`) |
| `scheduler` | `schedule:work` process alive (`pgrep`) |

## Notes

* mysql/redis have **no published ports** — reachable only inside the compose network.
* The `php` service publishes `127.0.0.1:8080` only (override with `APP_PORT`) — the host nginx is the only path in; the port is never exposed publicly.
* `laravel.log` persists on the `php_logs` volume (survives deploys); truncate via `prod-shell` when it grows.
* The image contains no `.env` file by design — generate keys with `php artisan key:generate --show` and set them in `.env.production`.
* Sessions/cache/queue use the `database` driver (tables come from normal migrations).
* The scheduler runs `app:cleanup-stuck-generations` every five minutes (added in `routes/console.php`).
* `config/scramble.php` must stay serializable (no object values) or AUTORUN's `optimize` fails.
